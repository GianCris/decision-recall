# Decision Recall — Decision Log

## D-001 — Concept phase closed
The conceptual phase is closed. New mechanisms are added only when evidence or a critical experimental flaw justifies them.

## D-002 — Evidence before Fleet infrastructure
Decision Recall must demonstrate its core mechanism before investing deeply in Fortified Enterprise Fleet infrastructure.

## D-003 — Discovery and Recovery evaluated separately
Discovery and Recovery will be experimentally isolated so that improvement in one cannot hide weakness in the other.

## D-004 — No mechanism is protected
Semantic Decision Lineage, Decision Sensitivity, Justification Trace, Reliance Load, counterfactual replay and every architectural hypothesis may be removed if evidence does not support them.

## D-005 — FLEET-1 v0.1 frozen before results
The FLEET-1 experimental protocol is frozen before the first meaningful experimental results. Changes require a documented methodological reason and must not be made to improve observed scores retroactively.

## D-006 — Collaborative Partner is the submission target
Decision Recall targets the Collaborative Partner category under the current All Things Agentic rules. The fit is structural: exactly one bounded human clarification captures knowledge the model cannot legitimately infer, while Decision Recall synthesizes that declaration into durable canonical state and later adapts evaluation as the world changes. Taskmaster's no-human-intervention emphasis conflicts with this trust boundary; Fortified Enterprise Fleet would require multi-agent enterprise scope not justified by the core mechanism. Reopen only if official rules materially change or implementation evidence falsifies the fit.

## D-007 — VWS-0.5 comprehension before frontend investment
Before implementing the production presentation adapter, Decision Recall must pass a static cold-viewer comprehension gate. No t0 screen may imply the unresolved Beacon historical role is true before the human YES.

## D-008 — Cloud Run and live Proof of Action are submission P0
Cloud Run is the minimum explicit Google Cloud infrastructure target before final recording. The submitted video must show a continuous, unedited live execution of the real agent path and visible Google Cloud deployment proof. Static/replay paths may support resilience and explanation but must be labeled and cannot replace Proof of Action.
